# Architecture

## 1. Principles

- Swift 6 with strict concurrency; app modules default to main-actor isolation, and callbacks delivered on background queues are built in `nonisolated` code.
- SwiftUI for every settings, popover, onboarding and HUD view; AppKit only for what SwiftUI cannot do: status item, transparent panels, event monitors and taps, cursor.
- Effects are rendered with Core Animation layers in overlay panels, never SwiftUI, so the 60 Hz loop stays cheap.
- A pure domain module holds models, rules and algorithms without AppKit, so it is unit-tested directly.
- One observable state (`AppModel`, `@Observable`) is the single source of truth.
- A local Swift package with one target per layer, plus an app target generated by XcodeGen from `project.yml`.

## 2. Modules

```text
Mickey/
├── project.yml                 # XcodeGen → Mickey.xcodeproj (not committed)
├── App/                        # App target: composition root, status item, windows, menu, review prompt, assets
└── Packages/MickeyKit/
    ├── Sources/
    │   ├── MickeyDomain/       # Settings and enums, SettingsRules, InteractionEngine, ShakeDetector, TrailBuffer,
    │   │                       # tap/hold recognisers, spotlight geometry, annotations, review policy,
    │   │                       # presenter-tool logic (keystroke formatting, magnifier geometry, focus selection,
    │   │                       # captions, presets, automatic mode)
    │   ├── MickeyPersistence/  # SettingsStore, JSON codec with field-level recovery, migrations
    │   ├── MickeySystem/       # InputMonitor, HotkeyRegistry, login item, sound, cursor, permissions,
    │   │                       # keystroke event tap, front window, app watcher
    │   ├── MickeyEffects/      # Overlay panels and renderers: spotlight, ring, trail, click effects, locator
    │   ├── MickeyAnnotations/  # Drawing canvas (AppKit) and toolbar (SwiftUI)
    │   ├── MickeyStudio/       # Keystrokes HUD, magnifier (live zoom, loupe), focus, camera bubble, captions,
    │   │                       # recorder, countdown, StudioCoordinator
    │   └── MickeyUI/           # AppModel, settings pages, popover, onboarding, help, hotkey recorder and conflicts
    └── Tests/                  # Domain, persistence, effects and UI logic suites
```

Dependencies: `Domain` ← everything; `Persistence` ← `UI`; `System` ← `Studio`; `Effects` ← `Annotations`, `Studio`, `UI`. `UI` does not depend on `System` or `Studio`: side effects go through the `AppActions` protocol implemented by the app's `AppDelegate`, which wires every module together.

## 3. State and flow

```text
              ┌──────────────── AppModel (@Observable) ────────────────┐
 SwiftUI ───▶ │ settings · permissions · recording · messages          │ ──▶ SettingsStore (debounced JSON)
 popover      │ update { … } → SettingsRules.normalize → onChange      │
 hotkeys ───▶ └──────────────────────────┬─────────────────────────────┘
                                         │ onChange(old, new)
                                   AppDelegate.apply
        ┌──────────────┬─────────────────┼──────────────────┬───────────────────┐
  InputMonitor   HotkeyRegistry   AnnotationController   EffectsEngine   StudioCoordinator
  (60 Hz tick)                                              ▲                  ▲
        └──── InteractionEngine → commands ─────────────────┴──── pointer ─────┘
```

- **One path for changes**: settings pages, the popover, hotkeys, presets and automatic mode all change settings through `AppModel`, so the cross-field rules (master auto-enable, exclusive spotlight triggers, menu bar or Dock) always apply.
- **Input loop**: `InputMonitor` polls the pointer and modifier flags at the update rate and forwards global clicks and scrolls. `InteractionEngine` turns them into commands (click effect, sound, locate, spotlight off, momentary drawing) and decides spotlight visibility; `EffectsEngine` renders in a Core Animation transaction without implicit animations; `StudioCoordinator` moves the magnifiers.
- **Lone modifier detection**: flag state carries left/right device bits; another key counts as pressed when the last key-down event is newer than the modifier press (per-key state is unreliable in the sandbox).

## 4. Windows

| Window | Implementation |
| --- | --- |
| Settings | Titled `NSPanel` 940 × 720 hosting `SettingsRootView`; Esc closes; reused |
| Onboarding | Titled panel hosting `OnboardingView` |
| Popover | `NSStatusItem` + transient `NSPopover` hosting `StatusPopoverView` |
| Effects | One borderless, transparent, click-through panel per screen, on all Spaces and over full-screen apps |
| Drawing | Non-activating panel on the screen under the pointer, plus a floating toolbar panel |
| Presenter tools | Click-through panels for focus, zoom, loupe, keystrokes, captions and countdown; a draggable panel for the camera bubble |

Window levels, counted down from the cursor level: focus −5, live zoom −4, effects −3, drawing −2, toolbars and HUDs −1. Live zoom and loupe capture the screen without Mickey's windows; the recorder keeps them so effects appear in recordings.

## 5. Activation policy

`LSUIElement` is set. `showInDock` switches between `.regular` and `.accessory`. A user launch opens Settings; a login-item launch (detected from the launch Apple Event) stays in the menu bar.

## 6. Sandbox

Entitlements: app sandbox, user-selected read-write files (the settings export is written, the settings import and the custom click sound are read) and app-scoped bookmarks (custom click sound), Movies folder read-write (recordings), camera, audio input. No network entitlement. Screen Recording, Input Monitoring and Speech Recognition are runtime permissions without entitlements.

## 7. Assets

The app icon (`scripts/make_app_icon.swift`) and the click sound (`scripts/make_click_sound.py`) are generated from code. Trail shapes, locator pointer and effects are drawn with paths.

## 8. Tests

| Level | Examples |
| --- | --- |
| Domain | shake detection on synthetic sequences, tap/hold recognisers, trail buffer, interaction rules, annotation session, undo and redo, annotation bounds, color contrast, preview layout, review policy, keystroke formatting and history, zoom geometry, focus selection, captions, presets, automatic mode, default hotkeys |
| Persistence | settings export and import (`SettingsTransfer`), exact defaults, round trip, invalid fields, clamping, migrations (v1 → v3), fields added later |
| Effects | spotlight hole, shapes |
| Annotations | image rendering of a drawing (cropped, transparent, nothing outside the canvas) |
| UI logic | model-level settings export and import (stubbed file panels), hotkey conflicts and key-equivalent parsing |

`./scripts/ci.sh` runs the tests, the localization check (`scripts/l10n.py`), regenerates the project and builds the app.

## 9. Release and distribution

- `.github/workflows/ci.yml` runs `scripts/ci.sh` (tests, localization check, build) on every push to `main` and every pull request.
- A `v*` tag runs `.github/workflows/release.yml`: version check against `project.yml`, tests, localization check, universal Release build, zip and SHA-256, GitHub release (notes from `docs/releases/<version>.md` plus the generated changelog), then the Homebrew tap.
- The app is signed ad hoc and not notarized. Homebrew requires signing and notarization only for the official `homebrew/cask` tap, so Mickey is distributed through its own tap, `Arrows78/homebrew-mickey`, with a single `Casks/mickey.rb` rendered from `packaging/homebrew/mickey.rb.in` by `scripts/render_cask.sh`.
- Homebrew applies the macOS quarantine to the download, so Gatekeeper blocks the first launch exactly as with the manual download; the cask prints the way around it as a caveat.
- The cask removes only the app's container and preferences on `zap`, never the recordings in `~/Movies/Mickey`.
- The tap update needs the `HOMEBREW_TAP_TOKEN` secret and is skipped without it.

## 10. Localization and accessibility

- Texts are localized with the English text as key (`tr` / `trf` in `MickeyDomain`, SwiftUI literals directly); English is the reference and the fallback. See [`LOCALIZATION.md`](LOCALIZATION.md).
- Reduce Motion (System Settings › Accessibility › Display) is honored by the effects engine (`ReducedMotion` in the domain decides the scale animation), the focus overlay, the HUDs, the onboarding and the settings cards.
- Controls carry VoiceOver labels and values; selected tools, colors and sidebar pages are announced as selected.
